## 1. Quick start

All intermediate results of the structural estimation (`.Rdata` files, estimate tables, bootstrap draws, and posterior type probabilities) are already included. To reproduce all tests, figures, and tables in the paper **without re-running the structural estimation**, set the working directory to the root folder (`Replication package/`) and run:

```r
source("main_results_tests_and_figure.R")
```

This reads the data and runs all non-parametric tests. It prints to the console the LaTeX code of every regression table and of the two parameter tables of the structural analysis (trembles, and type shares with LRT $p$-values). It also writes the five figures (`Figure*_R*.pdf`) to the root folder.

To re-run the structural estimation from scratch, see [Section 5](#5-workflow-and-order-of-execution). The estimation scripts are computationally intensive (1,000 random starting points and 1,000 bootstrap replications per model) and are parallelised.

## 2. Software requirements

The code was written and run in R (version 4.3 or later is recommended). The following packages are used:

| Package | Used by | Purpose |
|---|---|---|
| `tidyverse` (`dplyr`, `tidyr`, `readr`, `stringr`, `ggplot2`, ...) | all scripts | data manipulation, figures |
| `parallel` (base R) | estimation scripts | `mclapply`, `detectCores` |
| `numDeriv` | loaded by `data_cleaning.R` | numerical derivatives (loaded, not essential for the reported results) |
| `sandwich`, `lmtest` | `main_results_tests_and_figure.R` | HC1 robust standard errors, Wald tests |
| `gt` | `02_*.R` estimation scripts | exports the estimate tables to PDF (`results_*.pdf`) |

Notes on the environment:

- **Parallelisation.** The estimation and bootstrap scripts use `parallel::mclapply`, which relies on forking and therefore runs in parallel only on macOS and Linux. On Windows, `mclapply` with `mc.cores > 1` is not supported; set `n_cores <- 1` (serial, much slower) or run the scripts on macOS/Linux.
- **`gt::gtsave()` to PDF** requires the `webshot2` package and a Chrome/Chromium installation. This only affects the convenience PDF copies of the estimate tables (`results_*.pdf`); all numbers are also saved as CSV.
- **Figures** are saved with `ggsave()` using the base `pdf()` device (no Cairo required). Greek letters in labels are written as plotmath expressions for this reason.

## 3. Data

### 3.1 Source

`data_mobility.csv` is the raw oTree export of all 10 sessions (192 rows, one per participant; 2,258 columns). Participants are identified only by the random oTree `participant.code`.

`data_cleaning.R` downloads the same file from a public Dropbox link and saves it as `data_mobility.csv` in the current working directory (see [Section 10](#10-notes-and-caveats)). A copy of `data_mobility.csv` is included in the root folder and in each estimation folder; all copies are byte-identical.

### 3.2 Variables used

`data_cleaning.R` keeps the following raw oTree variables (dots in names are replaced by underscores):

| Raw variable | Renamed to | Content |
|---|---|---|
| `participant.code` | `participant_code` | anonymous participant identifier |
| `socmob_October2025.36.player.stars` | `player_stars` | performance class in the effort task: 3 = top tercile ($r_H$), 2 = middle ($r_M$), 1 = bottom ($r_L$); `NA` for spectators |
| `socmob_October2025.36.player.parent` | `parent_status` | parental status, recoded `green`→`High`, `yellow`→`Medium`, `red`→`Low`, `NA`→`Spectators`; factor with levels `Spectators, High, Medium, Low` |
| `socmob_October2025.36.player.child` | `child_status` | realised child status (colour coding, not recoded; `NA` for spectators) |
| `questions_October2025.1.player.top_third` | `belief_top` | stated probability (0–100) of being in the top performance tercile |
| `questions_October2025.1.player.middle_third` | `belief_middle` | stated probability (0–100) of being in the middle tercile |
| `questions_October2025.1.player.bottom_third` | `belief_bottom` | stated probability (0–100) of being in the bottom tercile |
| `socmob_October2025.1.player.total_order` | `question_1` … `question_36` | identifier of the question shown on each of the 36 screens (e.g. `q8_ne_ch`) |
| `socmob_October2025.1.player.position_order` | `right_left_1` … `right_left_36` | whether the two alternatives were displayed in swapped left/right order |
| `socmob_October2025.<k>.player.button_1` / `button_2` | `button_L_<k>` / `button_R_<k>` | left/right button pressed on screen *k* |

### 3.3 Coding of questions and alternatives

Alternatives are labelled `A1` … `A7`, which correspond to the mobility tables $f^1, \dots, f^7$ of Appendix A (`A1` = No Mobility, `A4` = Partial Mobility, `A7` = Full Mobility, `A2`/`A3` = asymmetric mobility M↔L and H↔M, `A5`/`A6` = Europe-/American-style; `A5` and `A6` are not used in the experiment). The treatment is encoded in the question identifier (`_no_`, `_po_`, `_ne_` → `no`, `positive`, `negative`).

| Question id | Pair of alternatives | Shown to |
|---|---|---|
| `q1` | A1 vs A4 | High, Spectators |
| `q2` | A4 vs A7 | High, Spectators |
| `q3` | A1 vs A7 | High, Spectators |
| `q4` | A2 vs A3 | High, Spectators |
| `q5` | A2 vs A3 | Medium |
| `q6` | A2 vs A7 | Medium, Spectators |
| `q7` | A3 vs A7 | Medium, Spectators |
| `q8` | A1 vs A7 | Medium |
| `q9` | A1 vs A4 | Low |
| `q10` | A4 vs A7 | Low |
| `q11` | A1 vs A7 | Low |
| `q12` | A2 vs A3 | Low |

Each question is asked once in each of the three meritocracy treatments. Members therefore answer 12 questions and spectators 18.

### 3.4 Objects created by `data_cleaning.R`

After sourcing `data_cleaning.R`, the workspace contains only two objects:

- **`df`** — wide data, 192 rows × 151 columns (one row per participant).
- **`df_long`** — long data, 2,592 rows (48 spectators × 18 + 144 members × 12), one row per participant × question actually seen, with columns `participant_code, player_stars, parent_status, child_status, belief_top, belief_middle, belief_bottom, q, question, right_left, button_L, button_R, meritocracy, alternatives, choice`. The variable `choice` (e.g. `"A7"`) is the alternative actually chosen, obtained by combining the button pressed with the left/right display order.

Naming conventions: `stima` = estimation; `tr` / `no_tr` = with / without tremble; `spec`, `high`, `med`, `low` = the four roles; `mob` = *Mobility* type, `mer` = *Meritocracy* type, `mobmer` = *Mobility & Meritocracy* type. In the "drop types" folder, `drop_X` removes type X only. In the "drop motives" folder, `drop_mobmer_mob` removes every type that requires the mobility motive (*Mobility* and *Mobility & Meritocracy*), and `drop_mobmer_mer` removes every type that requires the meritocracy motive (*Meritocracy* and *Mobility & Meritocracy*).

Each estimation folder is self-contained: its scripts `source()` files with relative paths, so **each estimation script must be run with its own folder as the working directory**. This is why `data_cleaning.R`, `data_mobility.csv`, `prefs_to_choices.R`, and `stima_pre_process.R` are replicated across folders. `main_results_tests_and_figure.R` must be run from the root folder; it reads estimation outputs from the subfolders.

## 5. Workflow and order of execution

```
data_mobility.csv ──► data_cleaning.R ──► df, df_long
                                              │
             ┌────────────────────────────────┼─────────────────────────────────┐
             ▼                                ▼                                 ▼
  prefs_to_choices.R ──► stima_pre_process.R  (in each estimation folder)   main_results_tests_and_figure.R
                               │                                             (root; needs the outputs below)
             ┌─────────────────┴──────────────────┐
             ▼                                    ▼
   01_*_1000starts_parallel.R  ──►  *_1000starts.Rdata
             │
             ▼
   02_*_se_*.R  ──►  results_*.csv/pdf, bootstrap_*.csv, posterior_*.csv, *_se_*.Rdata
             │
             ▼   (restricted models only; also needs the unrestricted stima_tremble_1000starts.Rdata)
   03_bootstrap_LRT_*.R  ──►  bootstrap_LRT_*.rds / .Rdata / _draws.csv
```

To reproduce everything from scratch, run the scripts in this order. Each block must be run from inside the indicated folder.

1. **`Clean version - no overlap - 5 types/`**
   `01_stima_tremble_1000starts_parallel.R` → `01_stima_no_tremble_1000starts_parallel.R` → `02_stima_tremble_se_bestmodel.R` → `02_stima_no_tremble_se_bestmodel.R`
2. **`Clean version - uniform - 5 types/`** — same four scripts, same order.
3. **`Clean version - no overlap - 5 types drop types/`**
   For each X in {`mob`, `mer`, `mobmer`}: `01_stima_tremble_drop_X_1000starts_parallel.R` → `02_stima_tremble_se_drop_X.R` → `03_bootstrap_LRT_drop_X.R`.
4. **`Clean version - no overlap - 5 types drop motives/`**
   For each X in {`mob`, `mer`}: `01_stima_tremble_drop_mobmer_X_1000starts_parallel.R` → `02_stima_tremble_se_drop_mobmer_X.R` → `03_bootstrap_LRT_drop_mobmer_X.R`.
5. **Root folder:** `main_results_tests_and_figure.R`.

The `03_` scripts in steps 3 and 4 also load the unrestricted fit `stima_tremble_1000starts.Rdata`. Both folders already contain a byte-identical copy of the file produced in step 1; if you re-run step 1, copy the new file into both folders before running the `03_` scripts. Apart from this, steps 1–4 are independent of each other. Step 5 needs the outputs of all four estimation steps: steps 1 and 2 for the figures and belief regressions, and steps 1, 3 and 4 for the two structural tables.

Reproducibility: all random draws are seeded (`set.seed(100)` for the starting points, `set.seed(123)` for the non-parametric bootstrap, `set.seed(10000 + b)` for replicate *b* of the parametric bootstrap LRT). Starting values and bootstrap indices are pre-generated before the parallel loop, so results do not depend on the number of cores.

### 6.2 Files shared by all estimation folders

#### `prefs_to_choices.R`

| | |
|---|---|
| **Reads** | Nothing. |
| **Produces** | In memory: the parser functions and the character vectors `prefs_high`, `prefs_medium`, `prefs_low`, `prefs_spectator`. |
| **Contains** | (i) A parser for preference strings (`parse_preference`, `evaluate_choices`, …). Notation: `>` strict preference, `=` indifference, `-` joins parts of one relation (merged through shared items via union-find and transitive closure), `;` separates the three treatments (order *Neg*; *No*; *Pos*). A binary choice (a, b) is evaluated to 0 if a is preferred, 1 if b is preferred, and `NA` if indifferent or incomparable. (ii) The full list of admissible preference profiles for each role, annotated with the type(s) they belong to. These are the profiles listed in Online Appendix A (Tables "Choice profiles"). |
| **Difference between folders** | In the *no overlap* folders each profile is assigned to one type only, following the refinement rule of Appendix E.1 (most parsimonious type). In the *uniform* folder a profile belongs to every type that can rationalise it ($\mathcal{P}^{(1)}_k(j)$), e.g. `#Self + Self_Mob + Self_Mer + Self_Mob_Mer`. |

#### `stima_pre_process.R`

| | |
|---|---|
| **Reads** | Sources `data_cleaning.R` and `prefs_to_choices.R`. |
| **Produces** | In memory: the profile matrices `profiles_{spec,high,medium,low}`, the likelihood function `negloglik`, and the estimation arrays `dati_stima_{spec,high,medium,low}` with participant ids `id_{spec,high,medium,low}`. |
| **Contains** | (1) Conversion of each preference profile into the implied vector of 12 binary choices. For Spectators, High and Low the order is `A1_A7, A1_A4, A4_A7, A2_A3` × (*Neg*, *No*, *Pos*); for Medium it is `A1_A7, A2_A7, A3_A7, A2_A3` × (*Neg*, *No*, *Pos*). For spectators only the 12 questions shared with High are used (A2–A7 and A3–A7 are excluded). (2) `evaluate_choice`: for every participant × profile, counts of choices aligned with (C), contrary to (S), and indifferent under (I) the profile. (3) `tremble_lik`: $(1-\varepsilon/2)^C(\varepsilon/2)^S(1/2)^I$. (4) `prob_profile_given_type_*`: matrices mapping profiles to types through the within-type probabilities $p(\succeq\mid k,j)$. (5) `negloglik`: the latent-class negative log-likelihood of Section 5, computed with `softmax` reparametrisations and `logsumexp` for numerical stability. (6) Construction of the participant × choice matrix (`1` = second alternative of the pair chosen, i.e. A7, A4 or A3) and of the 3-D arrays [participant × profile × (C, S, I)]. |

**Parameter vector.** In the *no overlap* model the parameter vector has 72 elements: `par[1:5]` are the unconstrained type shares (mapped by softmax to $\pi$ in the order *Selfish*, *Mobility*, *Meritocracy*, *Mob & Mer*, *Random*); `par[6:9]` are the trembles $\varepsilon_j$ for Spectators, High, Medium, Low (bounded in [0, 0.5]); `par[10:72]` are the nuisance within-type probabilities (Spectators 10–14, Low 15–19, Medium 20–37, High 38–72). In the *uniform* model the vector has 89 elements and all within-type parameters (`par[10:89]`) are pinned at 0, which makes the within-type probabilities uniform over $\mathcal{P}_k(j)$.

### 6.3 Main structural model — `Clean version - no overlap - 5 types/`

#### `01_stima_tremble_1000starts_parallel.R`

| | |
|---|---|
| **Reads** | Sources `stima_pre_process.R`. |
| **Produces** | `stima_tremble_1000starts.Rdata` (entire workspace). ### 6.5 Restricted models, one type removed — `Clean version - no overlap - 5 types drop types/`

For each X ∈ {`mob`, `mer`, `mobmer`}, the type X is removed from the unrestricted tremble model.

**How the restrictions are implemented.** Every restricted script (`01_`, `02_` and `03_`) defines three objects at the top: `drop_pi` (the types removed), `keep_pi` (the types retained) and `pin_idx` (the within-type parameters fixed by setting `lower = upper`). The restricted likelihood `negloglik_restricted` is the unrestricted `negloglik` of `stima_pre_process.R` with one change: the shares of the retained types are `softmax(par[keep_pi])` and the shares in `drop_pi` are set to exactly 0. The restricted model is therefore nested in the unrestricted one: evaluating the unrestricted likelihood with the raw shares in `drop_pi` set to −∞ gives exactly the restricted likelihood.

Because a dropped type receives zero weight, the within-type probabilities that feed *only* that type no longer enter the likelihood and are pinned, so that they do not create flat directions in the optimiser. Blocks shared with a surviving type remain free. The within-type parameter blocks of `stima_pre_process.R` feed the following types:

| Parameters | Role | Feeds type(s) |
|---|---|---|
| `par[10:14]` | Spectators | *Mob & Mer* |
| `par[15:19]` | Low | *Meritocracy* and *Mob & Mer* (shared: the two types admit the same profiles for Low) |
| `par[20:23]` | Medium | *Meritocracy* |
| `par[24:25]` | Medium | *Mobility* |
| `par[26:37]` | Medium | *Mob & Mer* |
| `par[38:42]` | High | *Meritocracy* |
| `par[43:47]` | High | *Mobility* |
| `par[48:72]` | High | *Mob & Mer* |

The *Selfish* and *Random* types, and the *Mobility* and *Meritocracy* types of Spectators and the *Mobility* type of Low, map to a single profile and have no within-type parameters. The five restricted models are:

| Model | Folder | Types dropped (`drop_pi`) | Parameters pinned (`pin_idx`) | Type-shares table |
|---|---|---|---|---|
| `drop_mobmer_mob` | drop motives | *Mobility*, *Mob & Mer* (2, 4) | 10:14, 24:25, 26:37, 43:47, 48:72 | column (2) |
| `drop_mobmer_mer` | drop motives | *Meritocracy*, *Mob & Mer* (3, 4) | 10:14, 15:19, 20:23, 26:37, 38:42, 48:72 | column (3) |
| `drop_mob` | drop types | *Mobility* (2) | 24:25, 43:47 | column (4) |
| `drop_mer` | drop types | *Meritocracy* (3) | 20:23, 38:42 | column (5) |
| `drop_mobmer` | drop types | *Mob & Mer* (4) | 10:14, 26:37, 48:72 | column (6) |

The Low block `par[15:19]` is pinned only in `drop_mobmer_mer`, where both types it feeds are removed. In `drop_mer` and `drop_mobmer` it remains free because it still feeds the surviving type. The same `drop_pi`, `keep_pi` and `pin_idx` are used in the `01_`, `02_` and `03_` script of each model.

| Script | Reads | Produces | Contains |
|---|---|---|---|
| `01_stima_tremble_drop_X_1000starts_parallel.R` | `stima_pre_process.R` | `stima_tremble_drop_X_1000starts.Rdata` | restricted `negloglik`; 1,000-start MLE as in 6.3 |
| `02_stima_tremble_se_drop_X.R` | `stima_pre_process.R`, `stima_tremble_drop_X_1000starts.Rdata` | `results_tremble_se_drop_X.{csv,pdf}`, `bootstrap_tremble_se_drop_X.csv`, `posterior_{spec,high,med,low}_tr_drop_X.csv`, `stima_tremble_se_drop_X.Rdata` | bootstrap SE and posteriors as in 6.3 |
| `03_bootstrap_LRT_drop_X.R` | `stima_pre_process.R`, `stima_tremble_1000starts.Rdata` (unrestricted), `stima_tremble_drop_X_1000starts.Rdata` (restricted) | `bootstrap_LRT_drop_X.rds`, `bootstrap_LRT_drop_X.Rdata`, `bootstrap_LRT_drop_X_draws.csv` | parametric bootstrap likelihood-ratio test (see below) |

**Parametric bootstrap LRT (`03_` scripts).** Because the restriction puts mixture weights on the boundary of the parameter space, the LR statistic does not follow a $\chi^2$ distribution. The script (1) computes the observed $LR = 2(\ell_{\text{full}} - \ell_{\text{restricted}})$; (2) builds the data-generating process under $H_0$ from the restricted MLE; (3) for each replicate $b$ (`set.seed(10000 + b)`) simulates a dataset of the same size and role composition, and re-estimates both models, keeping the best of several `nlminb` fits: the restricted model from 9 starts (its MLE plus `n_restarts = 8` random restarts) and the full model from 10 starts (its MLE, the restricted solution re-expressed as a full-model point, and 8 random restarts). Random restarts are drawn around the corresponding MLE (normal noise with SD 0.5 on the raw parameters, trembles from U[0, 0.15]). Offering the restricted solution to the full model ensures $LR^* \ge 0$ up to optimiser tolerance; residual negative values of order $10^{-5}$ are set to 0; (4) computes $p = (1 + \#\{LR^* \ge LR\})/(1 + B)$ over the $B = 1{,}000$ valid replicates. All five `03_` scripts use the same settings (`n_boot = 1000`, `n_restarts = 8`, all available cores via `detectCores()`, `mc.preschedule = FALSE` for load balancing). The reported LRT results were obtained on the MPCDF computing cluster. They are:

| Model | Log-lik. restricted | $LR$ | Largest $LR^*$ in 1,000 draws | #$\{LR^* \ge LR\}$ | $p$ |
|---|---|---|---|---|---|
| `drop_mobmer_mob` | −1167.877 | 151.58 | 21.25 | 0 | 0.001 |
| `drop_mobmer_mer` | −1154.665 | 125.16 | 21.55 | 0 | 0.001 |
| `drop_mob` | −1117.400 | 50.63 | 12.66 | 0 | 0.001 |
| `drop_mer` | −1098.792 | 13.41 | 13.69 | 1 | 0.002 |
| `drop_mobmer` | −1116.114 | 48.06 | 18.56 | 0 | 0.001 |

The unrestricted log-likelihood is −1092.086. With $B = 1{,}000$ the smallest attainable $p$-value is $1/1{,}001 \approx 0.001$, which the paper reports as $p < 0.001$.

## 7. Output file dictionary

### `results_*.csv`

Three columns: `parameter`, `estimate`, `se` (bootstrap standard error). Rows:

| `parameter` | Meaning |
|---|---|
| `pi_1_self` | share of *Selfish* type |
| `pi_2_self_mob` | share of *Mobility* type |
| `pi_3_self_mer` | share of *Meritocracy* type |
| `pi_4_self_mob_mer` | share of *Mobility & Meritocracy* type |
| `pi_5_rand` | share of residual *Random* type |
| `tremble_spec`, `tremble_high`, `tremble_medium`, `tremble_low` | role-specific tremble $\varepsilon_j$ |
| `best_start_id` | index of the best starting point |
| `Log_lik` | value of the minimised objective, i.e. the **negative** log-likelihood (the paper reports its negative, e.g. −1092.086) |
| `convergence` | `nlminb` convergence code of the best fit (0 = "relative convergence"; 1 = any other message). Code 1 typically corresponds to "singular convergence (7)", which is expected here because the within-type nuisance parameters are not identified in some directions; the same optimum is reached from many starting points (see `starts_tbl` in the `*_1000starts.Rdata` files). |

In the restricted models the dropped shares are reported as exactly 0 with SE 0; in the deterministic models the trembles are 0 with SE 0.

The `results_*.pdf` files are formatted copies of the same tables produced with `gt`.

### `bootstrap_*_se_*.csv`

1,000 rows (one per bootstrap replication) and 9 columns `V1`–`V9` in the order: $\pi_{\text{Self}}, \pi_{\text{Mob}}, \pi_{\text{Mer}}, \pi_{\text{MobMer}}, \pi_{\text{Rand}}, \varepsilon_{\text{spec}}, \varepsilon_{\text{high}}, \varepsilon_{\text{medium}}, \varepsilon_{\text{low}}$. Failed replications are `NA`.

### `posterior_<role>_<spec>_<model>.csv`

48 rows (one per participant of that role). The first column is the participant code (`id_spec`, `id_high`, `id_medium`, or `id_low`, matching `participant_code` in `df_long`); columns `type_1`–`type_5` are the posterior probabilities of *Selfish*, *Mobility*, *Meritocracy*, *Mobility & Meritocracy*, *Random*, summing to 1 in each row.

### `*.Rdata`

Each estimation `.Rdata` file stores the entire workspace at the end of the corresponding script (`save(list = ls())`), including the data arrays, the likelihood functions, the best fit `fit`, and (for `02_` files) `boot_results`, `results_tbl` and the posteriors. They can be inspected with `load("file.Rdata")`.

### `bootstrap_LRT_*.rds` / `_draws.csv`

The `.rds` file is a list with elements `model`, `LR_obs`, `ll_full_obs`, `ll_restr_obs`, `p_value`, `n_boot`, `n_valid`, `LR_boot`, `ll_full_boot`, `ll_restr_boot`, `boot_mat`. The `_draws.csv` file has one row per replicate with columns `replicate`, `lr`, `ll_full`, `ll_restr`, the five type shares and four trembles of the full model (`pi_full_*`, `tr_full_*`), and the same for the restricted model (`pi_restr_*`, `tr_restr_*`).

## 10. Notes and caveats

- **Data download.** `data_cleaning.R` always calls `download.file()` on the Dropbox link and overwrites `data_mobility.csv` in the working directory. If the link is unavailable or there is no internet connection, comment out the `url`, `dest` and `download.file()` lines; the script then reads the local copy of `data_mobility.csv`, which is identical to the online file.
- **Working directories.** Run `main_results_tests_and_figure.R` from the root folder and every estimation script from its own folder (see [Section 4](#4-folder-structure)). Folder names contain spaces; keep them unchanged, since they are hard-coded in `main_results_tests_and_figure.R`.
- **Computation.** The `01_` scripts (1,000 starts), the `02_` scripts (1,000 bootstrap replications) and the `03_` scripts (parametric bootstrap with refits of two models per replicate) are the time-consuming steps. All of them are parallelised with `mclapply` (see [Section 2](#2-software-requirements) for Windows).
- **Stochastic results.** The pre-saved outputs were obtained with the seeds listed in Section 5. Minor numerical differences may arise across platforms and R/BLAS versions due to floating-point differences in the optimiser.
